## D2 · Invariante 1 proyecto = 1 cliente + RLS

**Lectura senior.** El aislamiento multi-tenant de FULKRO es sólido y *fail-closed por diseño*, no por convención. La cadena completa es: `set_tenant_context` fija GUCs `app.current_client_id`/`app.current_project_id` con `is_local=true` (scope transacción · `database.py:34-57`) → las funciones SQL `current_client_id()`/`current_project_id()` devuelven `NULLIF(current_setting(...,true),'')::uuid` = **NULL si no hay contexto** (`infra/docker/init-functions.sql:13-19`) → las policies RLS comparan `client_id = NULL` / `project_id = NULL` que en SQL es siempre falso → **0 filas sin contexto** (default-deny).
